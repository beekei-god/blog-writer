# 글쓰기 규칙

## 의미
사용자가 화면에서 고칠 수 있는 마크다운 문서. 리서치 프롬프트와 글 작성 프롬프트에 그대로 들어가므로 **사실상 이 앱의 편집 방침**이다. 글 작성 프롬프트는 "내용과 문체는 규칙이 우선하고, 출력 필드 구조는 출력 형식을 따른다"고 지시한다 (`blog-writer:server/writer.ts:7`).

## 기본 규칙 요약 (`rules/default-writing-rules.md`)
| 장 | 핵심 | 코드가 강제하는 부분 |
|---|---|---|
| 1. 쉬운 문장과 단어 | 짧은 문장, 한 문장 한 정보, 어려운 용어 풀이(검색·공식 자료 근거), 숫자는 표·목록 | 프롬프트만 |
| 2. 존댓말 | 해요체/합니다체 통일, 반말·"~함" 금지 (표·소제목 명사형 허용) | 프롬프트만 |
| 3. SEO | 검색 질문 먼저, 메인 1·서브 2~3 롱테일, 제목 후보 3개 25~35자, 결론 먼저 도입부, 소제목 이모지, 문단은 한 가지 내용 1~3줄(길면 의미 단위로 나눠 문단 블록 여러 개, 짧은 내용은 한 줄 문단), 공백 포함 3,000자 이내, 핵심 요약, 1차 출처 링크, 저품질 행위 금지 | 분량([[writing/business-rules/BR-WRT-001 본문 분량 상한]]), 제목 후보 수([[writing/business-rules/BR-WRT-013 제목 후보와 키워드]]) |
| 4. 태그 | 30개 이내(화면에서도 30개에서 막음), 중요도 순, 절반 안팎은 자동완성·연관검색어, 출처·검색어·날짜 표, 고유명사 붙여쓰기 | [[writing/business-rules/BR-WRT-004 태그 최대 30개]], [[writing/business-rules/BR-WRT-005 태그 출처 검증]], 스마트블록은 충돌 → [[writing/business-rules/BR-WRT-006 스마트블록 주제 태그 금지]] |
| 5. 확인된 내용만 (가장 중요) | 이번 작업에서 확인한 자료만, 공식→언론→블로그, 블로그 수치 "참고용", 자료 차이는 "공고문 확인 필요", 못 찾은 항목은 본문에서 아예 뺌(빈 칸·"-"·"미정" 금지), 계산값 표시, 참고 자료 목록, 날짜 표시줄 금지 | [[writing/business-rules/BR-WRT-003 확인된 사실만 사용]], [[writing/business-rules/BR-WRT-007 빈 칸 있는 표 행 제거]], [[writing/business-rules/BR-WRT-008 날짜 표시줄 제거]] |
| 6. 소제목과 섹션 | 소제목+내용=섹션, 구분선 금지, 소제목 위에만 빈 줄 한 줄, 빈 블록 금지, 이미지는 설명 문단 바로 뒤 | [[publishing/business-rules/BR-PUB-007 소제목 위 빈 줄]] |

## 속성
| 속성 | 의미 |
|---|---|
| `content` | 규칙 본문 (1~50,000자) |
| `isDefault` | 수정본이 없어 기본 파일을 쓰는 중인지 |
| `updatedAt` | 수정본 파일 수정 시각 |

## 상태와 전이
기본 → (저장) 수정본 → (기본 규칙으로 되돌리기) 기본. 저장하면 **다음 작업부터** 적용 → [[writing/business-rules/BR-WRT-009 글쓰기 규칙 적용 시점]].

## 저장 위치
수정본 `<데이터 폴더>/writing-rules.md`(기본 `data/`, `BLOG_WRITER_DATA_DIR`로 바꿀 수 있음. 임시 파일에 쓴 뒤 이름 바꾸기 `writeFileAtomic`), 기본 `<프로젝트 루트>/rules/default-writing-rules.md`(서버를 어느 폴더에서 실행해도 `PROJECT_ROOT` 기준으로 찾는다, `blog-writer:server/rules.ts:11-12`), 작업별 사본 `Job.rulesSnapshot`. API는 `GET/PUT /api/rules`, `POST /api/rules/reset` (`blog-writer:server/routes/settings.ts:48-58`).
