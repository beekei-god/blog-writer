# 이미지 다시 만들기 플로우

## 목적
실패했거나 마음에 들지 않는 이미지를 한 장씩 다른 화풍·AI·방법(API/크롬)으로 다시 만들거나, 직접 올린 이미지로 바꾼다. 다른 이미지는 건드리지 않으며, 여러 장을 동시에 다시 만들 수 있다.

## 단계
| # | 단계 | 위치 | 관련 규칙 |
|---|---|---|---|
| 1 | 실패한 이미지 자리에서 실패 이유·안내 확인 | `FailedPlaceholder` | [[image/business-rules/BR-IMG-007 이미지 실패 격리와 원인 분류]] |
| 2 | 화면이 대기 중인 편집을 먼저 저장(`flush`) | `src/job/JobDetail.tsx` | |
| 3a | 이미지별 "이미지 다시 생성"(또는 "이미지 생성") → 창에서 **스타일 / 만드는 곳 / 만드는 방법**(Gemini·ChatGPT만, [○○ API \| 크롬], 키 없으면 API 비활성+툴팁)을 한 줄씩 고르고 버튼 하나 "이미지 다시 만들기"(또는 "이미지 만들기"). 처음 값은 글의 그 종류 AI·화풍, 방법은 `api`. 이 이미지에만 적용. 대상 키는 `thumbnail` 또는 `body-<블록 번호>` | `ImageTools`, `RegenRow`, `StylePicker`·`ProviderPicker`·`MethodPicker` | [[image/business-rules/BR-IMG-009 다시 만들기 범위]], [[image/business-rules/BR-IMG-013 이미지 API 우선과 만드는 방법 선택]] |
| 3b | 썸네일 없는 글: "썸네일이 없습니다" → 스타일 → AI 고르고(`AiPicker`) "썸네일 만들기". 방법은 글에 저장된 썸네일 방법 | `thumb-missing` | [[image/business-rules/BR-IMG-013 이미지 API 우선과 만드는 방법 선택]] |
| 3c | "직접 올리기" → 파일 선택 → 바이너리 업로드 → 바로 교체 | `ImageTools`, `POST /images/:target` | [[image/business-rules/BR-IMG-010 직접 올리기 형식과 크기]] |
| 4 | 서버: 한 장은 그 이미지나 다른 단계가 진행 중이면 409(다른 이미지만 진행 중이면 받음), 조합 검증, 옵션 저장 안 함, `markBusy(generating_images)` + `imageRunsOnly`, `runImage(target, ai, method)` → 202. 실행 옵션은 그 종류의 AI·화풍·방법만 이번에 덮어씀 (`imagesStep`) | `server/routes/images.ts`, `server/pipeline.ts` | [[image/business-rules/BR-IMG-002 AI별 허용 스타일]], [[image/business-rules/BR-IMG-014 한 장씩 다시 만들기 동시 실행]] |
| 5 | 진행 중에는 다른 이미지의 "이미지 다시 생성"·"직접 올리기"를 더 누를 수 있다. 만드는 중인 이미지는 "이미지를 만드는 중입니다"로 바뀌고 도구가 숨겨진다 | `PreviewImage`, `JobDetail` | [[image/business-rules/BR-IMG-014 한 장씩 다시 만들기 동시 실행]] |
| 6 | 이미지 생성 | | [[image/flows/이미지 생성 플로우]] |
| 7 | 마지막 진행이 끝나면 `draft_ready`. 화면은 job.updatedAt이 바뀌면 초안을 다시 받음 | `runImage` / `runImages` | |

## 실패 / 예외 경로
| 상황 | 결과 | 사용자에게 보이는 것 |
|---|---|---|
| 같은 이미지 진행 중, 또는 다른 단계 진행 중 | 409 | 오류 배너 |
| 불가 조합 | 400 | 오류 배너 |
| 대상 블록 사라짐 | 404 | "화면을 새로고침해 주세요." |
| 생성 실패 | 그 이미지에 실패 기록 | 이미지 자리의 실패 이유 |
| 작업 중지 | 동시에 도는 이미지 모두 중지 | "이미지 생성을 중지했습니다." |
