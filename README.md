# Blog Writer

주제만 입력하면 **자료 조사 → 글 작성 → 이미지 생성 → 블로그에 임시저장**까지 대신 해 주는 내 컴퓨터용 앱입니다. 발행 버튼은 항상 내가 직접 누릅니다(워드프레스는 예약·자동발행도 선택할 수 있습니다).

```
주제 입력 → Claude가 웹 검색으로 딥서칭 → 글쓰기 규칙에 맞춰 작성(본문 공백 포함 3,000자 이내)
        → 썸네일·본문 이미지 생성 → 초안 검토·수정 → 블로그에 올리기(임시저장) → 내가 발행
```

- 서버와 화면이 모두 **내 컴퓨터에서만** 돌아갑니다. 글, 이미지, 비밀번호는 `data/` 폴더에만 저장되고 git에는 올라가지 않습니다.
- Claude는 이미 로그인해 둔 **Claude Code**를 통해 부르므로 API 키가 필요 없고 API 요금도 나오지 않습니다(구독 한도를 씁니다).
- 지원 블로그: 네이버 블로그 / 티스토리 / 워드프레스.

## 1. 시작하기 전에 준비할 것

| 준비물 | 설명 | 필수 |
|---|---|---|
| Node.js 20 이상 | https://nodejs.org 에서 설치 (`node -v`로 확인) | 필수 |
| Claude Code | 터미널에서 `claude`를 실행해 **한 번 로그인**해 둡니다. 구독 계정이면 됩니다 | 필수 |
| 구글 크롬 | 평소 쓰는 크롬을 그대로 씁니다 | 필수 |
| Claude in Chrome 확장 프로그램 | https://claude.ai/chrome 에서 설치, Claude Code와 **같은 Claude 계정**으로 로그인 | 티스토리·네이버 올리기, Gemini/ChatGPT 이미지에 필요 |
| 블로그 계정 | 네이버·티스토리는 크롬에서 로그인해 두기, 워드프레스는 애플리케이션 비밀번호 | 올릴 블로그만 |
| 네이버 검색어 트렌드 키 | 주제 추천 순위를 매길 때만 (선택) | 선택 |

> 워드프레스에만 올리고 이미지는 Claude(SVG)로 만든다면 크롬 확장 프로그램 없이도 쓸 수 있습니다.

## 2. 설치와 실행

```bash
git clone https://github.com/beekei-god/blog-writer.git
cd blog-writer
npm install

claude          # 처음이면 로그인 후 종료 (이미 로그인했다면 생략)
npm run dev     # 서버(3001)와 화면(5173)을 함께 실행
```

브라우저에서 **http://localhost:5173** 을 엽니다. 종료는 터미널에서 `Ctrl + C`입니다.

환경 변수가 필요하면 `.env.example`을 `.env`로 복사해 고칩니다. 모두 선택 사항입니다.

| 변수 | 의미 |
|---|---|
| `PORT` | 서버 포트 (기본 3001). 바꾸면 `vite.config.ts`의 프록시 주소도 맞춰야 합니다 |
| `CLAUDE_MODEL` | 모델 별칭 (예: `opus`). 설정 화면에서 "Claude Code 설정"을 고를 때만 쓰입니다 |
| `DOWNLOADS_DIR` | Gemini/ChatGPT 이미지를 받는 폴더 (기본 `~/Downloads`) |
| `BLOG_WRITER_DATA_DIR` | 데이터 폴더 위치 (기본 프로젝트의 `data/`) |
| `CLAUDE_BIN` | `claude` 실행 파일 경로 (PATH에 없을 때) |
| `CHROME_PATH` | 크롬 실행 파일 경로 (자동으로 못 찾을 때) |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 네이버 검색어 트렌드 키 (설정 화면에서 넣어도 됩니다) |

## 3. 처음 한 번 하는 설정

화면 위쪽 **설정** 탭에서 합니다. 설정이 필요한 상태면 탭 옆에 점(●)이 보입니다.

### 3-1. 블로그 연결
쓸 블로그의 카드에서 블로그 주소(ID)를 입력해 저장합니다.
- **네이버 / 티스토리**: 크롬에서 해당 블로그에 로그인해 둡니다. 이 앱이 비밀번호를 저장하지 않습니다.
- **워드프레스**: [6-3](#6-3-워드프레스-rest-api)의 순서대로 사이트 주소·사용자명·애플리케이션 비밀번호를 넣습니다.

### 3-2. Claude in Chrome 연결 (네이버·티스토리·Gemini·ChatGPT를 쓸 때)
1. 크롬에 확장 프로그램을 설치하고 Claude Code와 같은 계정으로 로그인합니다. 처음이면 **크롬을 완전히 껐다 켭니다**.
2. 그 크롬에서 쓸 사이트(블로그, Gemini, ChatGPT)에 로그인해 둡니다.
3. 앱의 **설정 → Claude in Chrome → 1. 확장 프로그램 연결 → 연결 확인**을 눌러 초록 표시가 나오는지 봅니다.

작업 중에는 Claude가 크롬에서 화면을 보며 조작합니다. **Claude가 연 탭(그룹)은 작업이 끝날 때까지 건드리지 마세요.**

### 3-3. (선택) 모델, 글쓰기 규칙
- **Claude 모델 설정**: 단계별 모델을 고릅니다. 처음 쓴다면 기본값 그대로가 무난합니다. → [8장](#8-claude-호출-방식모델사용량)
- **글쓰기 규칙** 탭: 문체·분량·구성 규칙을 내 블로그에 맞게 고칩니다. → [5-3](#5-3-글쓰기-규칙)

## 4. 글 하나 쓰는 법 (따라 하기)

1. **새 글** 탭에서 **주제**를 적습니다. 예) `2026년 전기차 보조금 신청 방법`
   - 꼭 반영할 자료(공고문, 공식 안내 페이지)가 있으면 **참고 링크**에 한 줄에 하나씩 적습니다.
   - 주제가 막막하면 **주제 추천**에서 고르면 입력란이 채워집니다.
2. **이미지** 카드에서 썸네일 생성 여부, 본문 이미지 개수(0~6), 만드는 방식(Claude / Gemini / ChatGPT)과 스타일을 고릅니다. 모르겠으면 기본값으로 둡니다.
3. **딥서칭 시작**을 누릅니다. 목록의 상태가 차례로 바뀝니다.
   `딥서칭 중` → `글 작성 중` → `이미지 생성 중` → `초안 완료`
4. **초안 완료**가 되면 글을 눌러 초안을 검토합니다. 본문·제목·태그, 이미지 설명과 문구를 직접 고칠 수 있습니다.
   - 근거 출처와 이미지의 "근거 본문"을 확인하세요. 사실 관계는 **반드시 직접 확인**해야 합니다.
   - 이미지 속 한글이 틀렸으면 그 이미지만 **다시 만들기**를 합니다.
5. **블로그에 올리기**를 누릅니다. 네이버·티스토리는 에디터에 입력 후 **임시저장**까지 하고, 워드프레스는 임시저장/예약발행/자동발행 중에서 고릅니다.
6. 블로그에서 확인하고 **직접 발행**한 뒤, 앱에서 **발행 완료**로 표시하면 정리됩니다.

### 글 상태 한눈에 보기

| 상태 | 뜻 | 다음에 할 일 |
|---|---|---|
| 딥서칭 중 / 글 작성 중 / 이미지 생성 중 | 자동 진행 중 | 기다리기 (중지 가능) |
| 초안 완료 | 초안과 이미지가 준비됨 | 검토·수정 후 올리기 |
| 크롬 작성 중 / 워드프레스 등록 중 | 블로그에 올리는 중 | 크롬 탭을 건드리지 않기 |
| 임시저장 완료 | 블로그에 임시저장됨 | 블로그에서 확인 후 직접 발행 |
| 예약됨 | 워드프레스 예약발행으로 올림 | 시각을 기다리기 |
| 발행 완료 | 발행까지 끝남 | 없음 |
| 실패 | 어느 단계에서 멈춤 | 로그의 이유를 보고 다시 시도 |

앱을 껐다 켜면 진행 중이던 작업은 자동으로 정리됩니다. 목록 위의 필터 칩(전체·진행 중·초안 완료 …)으로 상태별로 볼 수 있습니다.

## 5. 화면별 안내

### 5-1. 새 글
주제, 참고 링크, 이미지 옵션을 입력해 글 작성을 시작합니다. 주제는 2자 이상이어야 하고, 링크는 `https://`로 시작해야 합니다.

### 5-2. 주제 추천
분야(예: `청약`, `전기차`)를 입력하면 **최근 2주 뉴스와 최근 발표된 통계·공고**를 찾아 주제 후보 10~12개를 만듭니다.
- 설정 → **네이버 데이터랩 설정**에 NAVER API HUB 검색어 트렌드 키(NCP 콘솔에서 발급)를 넣으면 최근 4주 검색 관심도와 상승세로 순위를 매깁니다. 관심도는 분야 대표 검색어의 평균을 100으로 놓은 상대값입니다.
- **이 주제로 글쓰기**를 누르면 주제와 근거 링크가 새 글 입력란에 채워집니다.

### 5-3. 글쓰기 규칙
Claude가 글을 쓸 때 따르는 규칙 문서를 화면에서 편집합니다.
- 기본값: `rules/default-writing-rules.md` (직접 고치지 않아도 됩니다)
- 내가 고친 값: `data/writing-rules.md` — **다음 작업부터** 적용됩니다.
- 기본값으로 되돌리려면 화면의 **기본 규칙으로 되돌리기**를 누릅니다.

### 5-4. 사용량
- **플랜 한도**: 5시간·주간 사용률(계정 전체). 화면 위쪽에도 항상 표시됩니다.
- **이 앱이 쓴 토큰**: 오늘·이번 주·최근 7일, 모델별·단계별.
- **지금 확인**: Haiku로 아주 짧은 요청을 한 번 보내 최신 한도를 받아 옵니다.

### 5-5. 설정
블로그 연결, 워드프레스, 네이버 데이터랩 키, Claude 모델, Claude in Chrome 상태를 관리합니다.

## 6. 블로그별 올리는 방법

### 6-1. 네이버 블로그 (macOS)
Claude in Chrome은 안전 정책상 네이버 같은 일부 사이트를 막습니다("This site is not allowed due to safety restrictions"). 이 앱은 제한을 우회하지 않고, **평소 쓰는 크롬의 새 탭에 AppleScript로 스크립트를 넣어** 에디터(SmartEditor ONE)에 붙여넣기 이벤트로 입력합니다. 이미 로그인된 크롬을 쓰므로 새 창이나 재로그인이 필요 없습니다.

처음에만 아래를 해 두세요.
1. 크롬 메뉴 **보기 > 개발자 > Apple Events의 자바스크립트 허용**을 켭니다.
2. macOS가 "Google Chrome 제어" 허용을 물으면 허용합니다 (시스템 설정 > 개인정보 보호 및 보안 > 자동화).

동작 방식:
- 소제목은 에디터의 "소제목" 서식으로 입력합니다(메뉴를 못 찾으면 굵은 글씨로 대체).
- 이미지는 JPEG(가로 최대 1600px)로 줄여 붙여넣습니다. 썸네일은 본문 첫 이미지가 됩니다.
- 태그는 발행 창에서만 입력할 수 있어 본문 마지막 줄에 `#태그`로 넣습니다. 발행할 때 직접 옮겨 주세요.
- 처음 막히면 그 자리에서 이어서 진행하고 `data/blocked-sites.json`에 기억해 다음부터는 바로 이 방법을 씁니다.

### 6-2. 티스토리, 그 밖의 블로그 / macOS가 아닌 경우
크롬을 앱 전용 프로필(`data/chrome-profile`)로 열어 글쓰기 화면을 조작합니다(`server/browser/adapters.ts`). 이 크롬은 평소 크롬과 **따로**라서, **설정 → Claude in Chrome → 2. 확장이 막는 블로그 → 네이버/티스토리 로그인 창 열기**로 한 번 로그인해 두세요. 임시저장까지만 합니다.

### 6-3. 워드프레스 (REST API)
크롬 없이 **REST API**로 올립니다. 올릴 때마다 **임시저장 / 예약발행 / 자동발행** 중에서 고릅니다(예약·자동은 확인 창을 거칩니다). 같은 글을 다시 올리면 새 글을 만들지 않고 이미 올린 글을 **갱신**합니다.

1. 설정의 **워드프레스 설정** 카드에 사이트 주소(`https://...`)를 넣어 저장합니다. https 사이트만 쓸 수 있습니다.
2. 워드프레스 관리자 → **사용자 → 프로필 → 애플리케이션 비밀번호**에서 이름을 아무거나 정해 비밀번호를 만듭니다(한 번만 보여 주니 바로 복사).
3. 앱의 워드프레스 설정에 **사용자명과 그 비밀번호**를 넣고 **연결 확인 후 저장**을 누릅니다. 값은 `data/secrets.json`(본인만 읽기)에만 저장됩니다.
4. 카테고리를 하나 고를 수 있습니다(비우면 사이트 기본 카테고리). 태그는 이름으로 찾고 없으면 만듭니다.

연결이 안 될 때: 보안 플러그인이나 호스팅이 REST API 또는 애플리케이션 비밀번호를 막고 있을 수 있습니다. 글쓴이 권한이 있는 사용자여야 하고, 자동발행·예약발행에는 "발행" 권한(편집자 이상)이 필요합니다. 이미지는 미디어 라이브러리에 올라가고 썸네일은 대표 이미지로 설정됩니다.

## 7. 이미지 생성

새 글 폼에서 썸네일 여부, 본문 이미지 개수(0~6), 만드는 방식을 고릅니다. 썸네일과 본문은 **서로 다른 AI·스타일**로 만들 수 있습니다(예: 썸네일은 Claude 플랫, 본문은 Gemini 실사). 처음에는 둘이 같은 값을 따라가고, 썸네일을 직접 바꾸면 따로 움직입니다.

| 방식 | 특징 | 필요한 것 |
|---|---|---|
| **Claude** | SVG 일러스트/인포그래픽을 그려 PNG로 변환. 도형·다이어그램 스타일(플랫만 가능). 가장 빠르고 안정적 | Claude Code |
| **Gemini / ChatGPT** | 크롬에서 웹 화면을 조작해 생성. API 과금 없음(각 서비스 한도 + Claude 사용량). 지브리풍·실사·애니메이션 가능 | Claude in Chrome, 해당 사이트 로그인 |

스타일: 지브리풍 / 실사 / 애니메이션 / 플랫 일러스트. 지브리풍은 서비스 정책상 거절될 수 있습니다.

**본문 기반 기획**: 이미지를 만들기 직전에 Claude가 본문을 다시 읽고, 이미지마다 그것이 놓인 섹션의 구체적인 대상·상황·수치가 보이도록 설명(prompt)을 쓰고 이미지 안에 넣을 문구(headline)를 정합니다.
- 썸네일: 클릭을 부르는 8~16자 문구를 가운데에 크게 넣습니다. 본문 이미지: 도움이 될 때만 짧은 제목·라벨(수치, 단계 이름)을 넣습니다. 문구는 본문에 있는 사실로만 만듭니다.
- 초안 편집 화면에서 이미지 설명이나 문구를 직접 고치면, 다시 만들 때 자동으로 바꾸지 않습니다("본문을 보고 자동으로 다시 정하게 하기"로 되돌릴 수 있음).
- 이미지 속 한글은 AI가 틀리게 그릴 수 있으니 **발행 전에 꼭 확인**하세요. 틀리면 해당 이미지만 다시 만들거나 Claude(SVG)로 만드세요.

**다시 만들기**: 초안 화면에서 "썸네일 다시 만들기…", "이미지 모두 다시 만들기…", 실패한 것만, 또는 한 장씩 다시 만들 수 있고 그때 AI를 바꿀 수 있습니다. 직접 만든 이미지 파일을 올려 교체할 수도 있습니다(png/jpg/webp/gif, 20MB 이하).

한 장이 실패해도 글 전체는 실패하지 않습니다. 실패한 이미지 자리에 이유와 해결 방법이 표시됩니다. Gemini/ChatGPT에서 이미지는 만들어졌는데 저장이 안 되면 [9장](#9-문제가-생겼을-때)을 보세요.

생성된 파일은 `data/images/<jobId>/`에 저장되고, 블로그에 올릴 때 에디터(워드프레스는 미디어 라이브러리)에 업로드됩니다.

## 8. Claude 호출 방식·모델·사용량

로컬 `claude -p` CLI를 자식 프로세스로 실행합니다(구독 한도 사용, API 과금 없음). 딥서칭은 WebSearch/WebFetch만 허용하고 MCP·파일 도구는 끕니다.

**모델** — 설정 → Claude 모델 설정에서 단계마다 Fable·Opus·Sonnet·Haiku 중에서 고릅니다. 기본값은 단계별 추천입니다.

| 단계 | 기본 모델 | 이유 |
|---|---|---|
| 자료 조사, 글 작성 | Opus | 정확도·문장 품질 |
| 이미지(SVG), 브라우저 조작, 주제 추천 | Sonnet | 속도·한도 절약 |

"Claude Code 설정"을 고르면 `.env`의 `CLAUDE_MODEL`, 없으면 Claude Code에 설정된 모델을 씁니다.

**사용량** — 호출 기록은 `data/usage.jsonl`(90일 보관), 마지막 한도 값은 `data/plan-limits.json`에 저장됩니다. 5시간·주간 한도가 부족하면 작업이 멈출 수 있으니 긴 작업 전에 사용량 탭을 확인하세요.

**태그 수집** — 리서치에서 정한 키워드로 네이버 **자동완성**과 **함께 많이 찾는**(예전 연관검색어 자리)을 수집해 태그 후보로 씁니다. "함께 많이 찾는"은 공개 API가 아니라 검색 화면 내부 요청이라 바뀔 수 있고, 네이버가 검색어별로 꺼 두면 비어 있습니다. 수집 목록에 없는 표현을 출처로 단 태그는 서버가 빼고 로그에 남깁니다.

## 9. 문제가 생겼을 때

글 상세 화면의 **진행 로그**에 어느 단계에서 무엇을 했는지 남습니다. 실패하면 먼저 로그와 실패 안내 상자를 읽어 보세요.

| 증상 | 확인할 것 |
|---|---|
| 화면이 안 열림 / 오류 | 터미널에 `npm run dev`가 떠 있는지, 3001·5173 포트를 다른 프로그램이 쓰고 있지 않은지 |
| 글 작성 단계에서 바로 실패 | 터미널에서 `claude`가 로그인된 상태인지, 사용량 탭에서 5시간·주간 한도가 남았는지 |
| "Claude in Chrome이 연결되지 않았습니다" | 크롬에 확장 설치·로그인 여부, 크롬을 껐다 켰는지, 설정에서 **연결 확인** |
| "로그인이 필요합니다" | 평소 쓰는 크롬에서 해당 사이트(블로그·Gemini·ChatGPT)에 로그인한 뒤 다시 시도 |
| "화면에서 진행하지 못했습니다" | 크롬에 확인 창(사이트 권한, 약관 동의 등)이 떠 있는지 보고 다시 하거나 다른 AI로 만들기 |
| "이미지를 저장하지 못했습니다" | 이미지는 만들어졌지만 파일을 못 받은 경우입니다. 여러 장을 연달아 만들 때 첫 장만 되면 크롬이 연속 다운로드를 막은 것일 수 있습니다. 주소창 오른쪽 다운로드 차단 표시에서 허용하거나 `chrome://settings/content/automaticDownloads`에서 해당 사이트를 허용하고, "다운로드 전에 각 파일의 저장 위치 확인"을 끄세요. 받는 폴더가 다르면 `DOWNLOADS_DIR`을 지정하세요 |
| "요청이 거절되었습니다" | 정책상 만들 수 없는 요청입니다. 다른 스타일(플랫)이나 Claude(SVG)로 다시 만들기 |
| "생성 한도를 다 썼습니다" | 한도가 풀릴 때까지 기다리거나 다른 AI로 만들기 |
| 네이버에 입력이 안 됨 | [6-1](#6-1-네이버-블로그-macos)의 "Apple Events의 자바스크립트 허용"과 macOS 자동화 허용 |
| 워드프레스 연결 실패 | https 주소인지, 애플리케이션 비밀번호·사용자명이 맞는지, 보안 플러그인이 REST API를 막지 않는지 |
| 크롬이 사용 중이라고 나옴 | 앱 전용 크롬(`data/chrome-profile`) 창이 이미 열려 있으면 닫고 다시 시도 |

Claude in Chrome에 주는 작업 안내(프롬프트)는 `server/browser/blogPost.ts`(블로그별 에디터)와 `server/images/webAi.ts`(Gemini/ChatGPT)에 있습니다. 크롬에는 Claude가 연 탭이 그대로 남아 있어 어디서 멈췄는지 볼 수 있습니다.

## 10. 내 데이터와 보안

모든 데이터는 `data/` 폴더에 로컬 파일로만 저장되며 `.gitignore`로 git에서 제외됩니다. 이 폴더와 `.env`는 **다른 사람에게 공유하거나 올리지 마세요.**

| 경로 | 내용 |
|---|---|
| `data/settings.json` | 블로그 설정 |
| `data/secrets.json` | 워드프레스·데이터랩 비밀번호/키 (본인만 읽기 권한) |
| `data/jobs/<id>.json` | 글 하나의 주제, 리서치 노트, 출처, 초안, 진행 로그 |
| `data/images/<id>/` | 생성된 이미지 |
| `data/writing-rules.md` | 내가 고친 글쓰기 규칙 |
| `data/usage.jsonl`, `data/plan-limits.json` | 사용량 기록(90일), 마지막 한도 값 |
| `data/blocked-sites.json` | Claude in Chrome이 막아서 대체 방법을 쓰는 사이트 |
| `data/chrome-profile/` | 앱 전용 크롬 프로필(로그인 정보 포함) |
| `data/recommendations/` | 주제 추천 결과 |

- 서버는 로컬 접속만 받도록 되어 있습니다.
- 앱을 다른 컴퓨터로 옮기려면 `data/`를 복사하면 되지만, 비밀 정보가 들어 있으니 안전한 방법으로 옮기세요.

## 11. 개발자용 정보

### 구조
```
server/   Express API 서버 (글 작성 파이프라인, Claude 호출, 이미지, 블로그 올리기, 사용량)
  browser/  크롬 조작 (Claude in Chrome 안내문, 네이버 AppleScript, 앱 전용 크롬)
  images/   이미지 기획·SVG·Gemini/ChatGPT 생성
  routes/   HTTP 엔드포인트
src/      React 화면 (Vite)
shared/   서버·화면이 함께 쓰는 타입과 규칙(라벨, 이미지 오류 분류 등)
rules/    기본 글쓰기 규칙 문서
tests/    vitest 자동 테스트
vault/    Obsidian 지식 문서 (아래 참고)
data/     내 데이터 (git 제외)
```

### 명령어
```bash
npm run dev         # 서버(tsx watch)와 화면(vite) 동시 실행
npm start           # 서버만 실행
npm run build       # 화면 빌드
npm run typecheck   # 타입 검사 (npx tsc --noEmit과 동일)
npm test            # 자동 테스트 (임시 데이터 폴더를 써서 실제 data/를 건드리지 않음)
```
코드를 바꾼 뒤에는 `npx tsc --noEmit`과 `npm test`를 돌려 확인합니다.

### 업무 규칙 wiki
`vault/wiki/`에 이 프로젝트의 업무 규칙·흐름·모듈 구조가 도메인별(글 작성, 이미지, 블로그 등록, 주제 추천, 사용량)로 정리되어 있습니다. Obsidian으로 `vault/` 폴더를 열어 읽을 수 있고, 시작점은 `vault/wiki/index.md`입니다. 코드를 읽고 만든 요약이라 낡았을 수 있으니, 다르면 코드를 기준으로 합니다. 작업 지침은 `CLAUDE.md`에 있습니다.
